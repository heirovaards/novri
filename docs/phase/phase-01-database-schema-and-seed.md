## Goal
The complete database: every table, enum, constraint and index in TRD §10; the audit trigger on every business table; reference seed data. After this phase the schema should not need structural changes.

## Read first
TRD §10 (data model, column by column), §19 (audit), §20.1 (Better Auth config, needed to generate the auth tables), §12 (TS mapping) · PRD §13 (seed), §4 (concepts).

## Out of scope
Login pages, session helpers, any action/query/screen, demo business data beyond what is listed here.

## Steps
1. Write `authInstance` (final configuration) and generate `auth-schema.ts`. Add `must_change_password` as an additional user field.
2. Write enums, shared column sets, then tables in dependency order: core → access → master → identitas → criteria 1 → 2 → 3–6 → files/audit.
3. Apply the conventions in TRD §10.1: uuid primary keys everywhere (including join and child tables), partial unique indexes `where deleted_at is null` on workflow tables, `(prodi_id, status)` index on workflow tables, indexes on every foreign key.
4. Nullable vs required: on workflow tables only identity columns are `NOT NULL` (drafts may be incomplete, TRD §10.6 note).
5. `pnpm db:generate`, review the SQL, `pnpm db:migrate`.
6. Audit: write `audit_row()` (TRD §19.1). `applyAuditTriggers` creates a trigger on every business table; child tables pass `(fk_column, parent_table)`. Keep the list of tables and parents in one constant inside that file. Skip `audit_log`, `session`, `verification`, `import_job`, `period_snapshot`.
7. Seeds (idempotent upserts):
   - organisation: FBTI + Prodi SI (PRD §13.1);
   - academic years 2018/2019–2035/2036;
   - reference lists exactly as PRD §13.2, in order, with `meta.defaultSks` for `jabatan_struktural`;
   - `prodi_setting` `ewmp_sks_range` = `{ "min": 12, "max": 16 }`.
8. `db:reset` script (refuses in production).

## Rules to honour
- Never store TS labels; only `academic_year_id`.
- Money columns `bigint`; decimals `numeric(8,2)` (`numeric(5,2)` for percentages).
- Reference-list values are `ref_option` foreign keys, not enums.
- Migrations are generated, committed, never hand-edited after being applied.

## Tests (integration, against `lkps_test`)
- Migrations apply from empty; `applyAuditTriggers` is idempotent (run twice).
- Insert, update, delete on a parent table inside `withActor` writes three `audit_log` rows with the actor, before/after JSON and `prodi_id`.
- A child-table write records `parent_entity_type` and `parent_entity_id`.
- A write outside `withActor` records a null actor (documented behaviour).
- Partial unique: two live `ewmp` rows for the same dosen + year fail; after soft-deleting one, inserting again succeeds.
- `lkps_period`: a second `open` period for the same prodi fails.
- Seeds are idempotent (run twice, same row counts).
